## 🛡️ Flagship · SellerGuard

<img src="https://img.shields.io/badge/🟢_Open_Beta-0096C7?style=for-the-badge" /> <img src="https://img.shields.io/badge/Solo_Planning_·_Dev-090979?style=for-the-badge" />

**온라인 셀러가 주문·발주·정산·세금 일을 한 곳에서 하는 SaaS** · 🔗 [sellerguard.kr](https://sellerguard.kr)

</div>

<p align="center">
  <img src="assets/sellerguard-dashboard.webp" width="49%" alt="SellerGuard 순이익 화면 (예시 데이터)" />
  <img src="assets/sellerguard-products.webp" width="49%" alt="SellerGuard 상품별 순이익 화면 (예시 데이터)" />

**문제** · 스마트스토어·쿠팡 셀러는 매출은 바로 보이지만, 수수료·택배비·광고비·원가를 뺀 진짜 남은 돈은 엑셀로 직접 맞춰 봐야 압니다. 마켓마다 정산 파일이 달라서 정산이 빠져도 모르고 지나가고, 공급처 발주서와 부가세 자료도 매번 따로 만듭니다.

**타깃과 포지셔닝** · 스마트스토어·쿠팡·테무 등 여러 마켓에서 혼자 파는 소규모·위탁 셀러. 첫 약속은 **"매출 말고 진짜 남은 돈"** 하나로 잡고, 그 뒤에 발주·정산·세금 일을 붙였습니다.

**피벗** · 처음 기획은 경쟁사 가격·리뷰 모니터링이었습니다. 가격 수집에 쓰려던 공식 API가 종료되고 자동 수집은 약관으로 막혀 있어 핵심 기능을 오래 유지할 수 없다고 판단했습니다. 셀러 커뮤니티에서 반복해서 나오는 고민(정산·현금흐름·순이익)을 근거로 2026년 10월에 방향을 바꿨습니다.

**솔루션 흐름**

```mermaid
flowchart LR
  A["판매자센터 엑셀 올리기<br/>(주문·정산)"] --> B["브라우저에서<br/>고객 개인정보 제거"]
  B --> C["상품별 진짜 순이익"]
  C --> D["정산 누락·금액 차이 찾기<br/>→ 마켓 문의 글 만들기"]
  C --> E["손해 상품 · 들어올 돈 달력"]
  C --> F["공급처별 발주 메일<br/>부가세 자료 · 월말 결산 엑셀"]
```

**기획 의사결정**

- **신뢰 장벽 낮추기** · 마켓 비밀번호나 API 키를 받지 않고 엑셀 업로드만으로 동작. 고객 이름·연락처·주소는 브라우저에서 걸러 서버에 저장하지 않음
- **가입 전에 가치 확인** · 유입에 비해 가입이 적다는 퍼널 데이터를 보고, 가입 없이 예시 가게 장부로 모든 기능을 써 보는 둘러보기를 추가. 내 파일을 올리는 순간에 가입하도록 설계하고 구글 계정 가입도 지원
- **데이터로 콘텐츠 운영** · 공식 검색 트렌드 API로 셀러 검색어를 조사해 블로그 주제를 정하고(30여 편 발행), 글마다 꼬리표 링크를 달아 방문과 가입을 추적
- **수익 모델** · 무료 + 3단계 구독(월 7,900 · 29,900 · 99,000원). 마켓 수, 기록 기간, 발주·결산 기능으로 구분. 2026년 12월까지 전 기능 무료 베타, 2027년 1월 유료 전환 예정
- **공공 데이터 연결** · 기업마당 공식 API로 셀러가 신청할 수 있는 정부·지자체 지원사업을 모아 보여 주는 화면을 추가(검색 유입과 재방문 목적)
- **혼자 운영할 수 있는 품질 관리** · 개발팀 없이 Claude Code·Antigravity 등 AI 코딩 에이전트로 구현. 단위 테스트 260여 개와 실제 사이트 화면 테스트를 배포마다 돌려 확인

**현재 상태와 다음 단계**

- 오픈 베타 운영 중(2026년 11월~). 실제 셀러 파일로 양식 인식을 넓히는 단계
- 추적 중인 퍼널: 글별 유입 → 둘러보기 → 가입 → 첫 파일 업로드 → 유료 전환
- 다음 계획: 쿠팡 주문·정산 자동 불러오기, 유료 전환 후 전환율·이탈률 공개

### 코딩 교재 6종 → 학원 교재 제작 대행

<img src="https://img.shields.io/badge/On_Sale_·_Kmong-0096C7?style=flat-square" /> <img src="https://img.shields.io/badge/Planning_·_Build_·_Sales-090979?style=flat-square" />

**발견한 문제** · 코딩 강사로 일하면서, 처음 맡는 과목이나 전공이 아닌 과목은 수업 준비에 시간이 많이 들고 강사마다 수업 품질이 달라진다는 점을 직접 겪음

**만든 것** · 화면에 띄우면 바로 수업할 수 있는 강사용 웹 교재 6종(자바 AP CSA · HTML/CSS/JS · 파이썬 · C · C++ · C#). 2026년 10월 크몽 판매 시작. AI 코딩 에이전트로 만들고 예제는 전부 실행해서 확인
- 선생님 노트, 차시별 일정표, 학생용 · 정답지 워크시트
- 발표 모드: 장 본문을 16:9 슬라이드로 자동 구성. 실행 결과와 정답은 →로 하나씩, 긴 정답은 다음 장에
- 예제를 실제로 컴파일 · 실행하는 검증 스크립트, 슬라이드 넘침 · 정답 노출 자동 점검
- 자바: 2025-26 AP CSA 개편 반영, AP 유형 문제 세트(객관식 14 · FRQ 4, 모든 코드를 실행해 정답 검증)

**피벗 (2026.11)** · 학원에 직접 제안해 보니 완성 교재보다 "우리 학원 자료로 만든 교재"를 원하는 반응이 있었고, AP 강사에게서 "학원이 가장 힘든 건 시험 유형 문제 만들기"라는 피드백을 받음. 주력을 학원 자료를 웹 교재로 만들어 주는 **제작 대행**으로 바꾸고, 6종은 예시이자 크몽 상품으로 둠. 피드백을 받은 뒤 AP 유형 문제 세트를 만들어 샘플에 추가

**품질 개선** · 교재에서 "AI로 만든 티"가 난다고 판단해 6종을 새 기준으로 다시 씀(그림, 시작 전 진단, 예측 → 고치기 → 순서 맞추기 → 추적표 → 작성 순서의 연습, 3단계 힌트). 디자인도 학습지풍으로 바꿈

**판매 설계** · 크몽: 개인 강사 / 소규모 학원 / 학원 전체 3단계 패키지. 제작 대행: 그 학원 자료로 한 단원을 먼저 만드는 파일럿부터

**현재** · 학원 대상 제안을 보내며 첫 고객 사례를 만드는 단계. 30곳의 회신을 모은 뒤 상품과 문구를 다시 판단합니다. 결과는 숫자로 업데이트할 예정입니다.

### 학습이룸 Change Maker TR2 — 수산물 직거래 아이디어 'Today-sea'

<img src="https://img.shields.io/badge/🏆_Grand_Prize-D4A017?style=flat-square" /> <img src="https://img.shields.io/badge/Design_Thinking_·_SDGs-090979?style=flat-square" />

**문제 정의** · 수산업 현장에서는 상품성이 낮거나 규격에 맞지 않는다는 이유로 아직 먹을 수 있는 수산물이 대량 폐기되는 반면, 소비자는 유통 단계마다 마진이 붙어 신선한 수산물을 상대적으로 비싸게 구매하는 구조적 비효율이 존재함

**아이디어** · 버려질 수산물을 어민에게서 직접 받아, 대학가 자취생 · 1인 가구에게 시세보다 싸게 연결하는 직거래 플랫폼

**활동**
- 디자인씽킹 프로젝트: 경험/주제 선정 → 사용자 공감(어민·대학상권 양측 인터뷰) → 문제 정의 → 프로토타입 & 사용자 테스트 → 결과물 발표
- 지역 문화자원을 활용한 SDGs 메시지 탐색 및 창의적 문제해결 워크숍(협력 체험) 참여
- 타 대학 학생들과의 팀빌딩 및 다학제 간 협업 경험

**결과** · 팀으로 'Today-sea' 아이디어를 기획하고 프로토타입을 만들어 최종 발표에서 **대상** 수상

**참여 목적** · 전공이 다른 학생들과 짧은 기간 안에 문제를 정하고 프로토타입까지 만들어 보기 위해 참여

### 플랜핏 케이스 스터디 — 비동기 소셜 기능 행동 실험

<img src="https://img.shields.io/badge/Behavioral_Experiment-0096C7?style=flat-square" /> <img src="https://img.shields.io/badge/PHALANX_Club_Project-090979?style=flat-square" />

<sub>PHALANX 기획 동아리에서 진행한 자체 케이스 스터디이며, 플랜핏 회사와는 관계가 없습니다.</sub>

**질문** · 운동 앱 '플랜핏'이 미국 시장에 진출한다고 가정할 때, 사용자가 운동을 꾸준히 이어가게 하려면 무엇이 필요할까

**가설** · 같은 시간에 함께하지 않아도 서로의 운동을 느끼게 하는 비동기 소셜 장치가 지속률을 높일 것

```mermaid
flowchart LR
  H["가설: 비동기 소셜 장치가 지속률을 높인다"] --> E["Wizard of Oz 13주 실험"]
  E --> P["규모 피벗: 5팀 → 3팀 18명 → 4팀 20명"]
  P --> R["긍정 반응 85.8% (n=28) · 목표 달성률 82.5%"]
  R --> X["종료 후 자율 커뮤니티로 전환"]
```

**실행**
- '고스트 싱크(Ghost Sync)', '달성률 동기화' 등 사용자 반응 기반 비동기 소셜 기능 기획
- 5주간 기획 아티클 연재
- 개발 리소스 없이 텍스트 기반 Ghost Sync 로직을 설계하고 Wizard of Oz 방식으로 13주간 직접 검증
- 5팀 → 3팀(18명) → 4팀(20명)으로 실험 규모 피벗, 카카오톡 오픈채팅 + 구글폼/시트 자동 집계로 실사용자 데이터 수집

**결과** <sub>(참여자 20명 안팎의 소규모 실험 결과입니다)</sub>
- Ghost Ping 긍정 반응 **85.8%** (n=28)
- 하이브리드(홈트/야외) 인증 **45.2%**
- 목표 달성률 **82.5%**
- 4일차에 참여도가 40점까지 떨어진 뒤, 직접 개입해 5일차에 70점으로 회복
- 챌린지 종료 후 강제 인증을 없애고 지인 초대를 열어 자율 커뮤니티로 전환
- 개발에 들어가기 전에 행동 실험으로 가설부터 확인하는 방식을 직접 해봄
